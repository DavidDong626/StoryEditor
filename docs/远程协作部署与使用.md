# 远程协作部署与使用

版本：v0.2 协作 Alpha · 2026-10-11

## 本机启动

安装 Node.js 24 LTS，然后在项目目录执行：

```sh
npm ci
npm run dev:all
```

打开 `http://127.0.0.1:5173/`。前端 5173 通过代理访问协作服务 3001；开发模式只监听本机。单独运行 `npm run dev` 只启动前端，要协作还需要 `npm run server:dev`。

点击侧栏“远程协作”或顶栏“接入远程协作”。账号名称 2–40 个字符，密码至少 10 位。注册和登录使用自己的协作服务，不依赖 Arcweave 账号。

## 团队使用

1. 所有者打开本地故事，登录后选择“将当前本地项目发布到协作服务”。会创建独立项目 ID，本地版本保持独立。
2. 所有者生成编辑者或查看者邀请链接，自己发送给成员。每份链接只能用一次，有效期 24 小时；不同成员分别生成链接。
3. 成员打开相同部署地址，注册 / 登录，再接受邀请。最多 5 位成员，包括所有者；同一账号多标签页不占额外成员名额。
4. 从“我的协作项目”打开项目。选择节点先查看，再点“开始编辑”；完成后点“结束编辑”或切换节点。正文、逻辑、出口和位置属于同一节点占用。
5. 不同节点可以并行修改。连线和删除等结构操作会临时占用涉及对象，若被其他成员占用则拒绝保存并保留草稿。
6. 等待“已保存到服务端”再切换项目或退出。试跑使用打开时的固定项目副本，不修改正式变量默认值。

所有者可以管理成员、改变编辑 / 查看权限和恢复快照；编辑者可以创作、导出和创建快照；查看者可以浏览与试跑。服务器对接口和 WebSocket 订阅都检查权限，移除成员时关闭其项目连接。

项目内容已经发送给有读取权限的浏览器，因此“查看者禁止导出”指应用功能和服务端导出接口限制，无法阻止有读取权限的人自行记录屏幕或读取已收到的数据。

## 断线与冲突

断线时停止新编辑，客户端自动重连并获取当前权威快照；租约失效后需要重新点击“开始编辑”。服务端尚未确认的完整稿先写入独立 IndexedDB。

发生冲突后不会继续提交积压命令，也不会用旧稿替换服务端。打开“协作与成员”，下载当前草稿或“保留的本机草稿”，然后选择“重新加载服务端版本”。对照备份手动合并需要保留的内容。清理浏览器站点数据会同时清理这些本机草稿；下载文件是独立副本。

重新打开浏览器后，可在协作窗口查看仍保留的未确认草稿。恢复服务端快照会让旧 epoch 的命令失效；如果当时有人有未提交内容，也应先导出其草稿再合并。

协作撤销只撤销当前会话中自己的一个服务端命令，且相关对象的版本必须没有被后续写入触及；不会撤销别人的修改。目前不支持协作重做，也不保证连续撤销同一对象的多条历史操作。

## 公网部署：Docker Compose + HTTPS

准备 Linux 服务器、Docker Compose，以及指向该服务器的域名。开放 80 / 443 以便 Caddy 自动签发和续期证书。此配置只有 HTTPS 入口对外，协作进程和 SQLite 数据库在内部网络。

```sh
cp .env.example .env
# 将 .env 中 DOMAIN 改为真实域名，例如 story.your-team.com
docker compose up -d --build
```

打开 `https://你的域名/`。Caddy 同时代理页面、API 与 WebSocket；账号 Cookie 自动带 Secure。`PUBLIC_ORIGIN` 必须与用户实际访问地址完全一致，不能混用其他域名或端口。

第一次按团队需要注册账号。若团队账号全部建立，可把 `.env` 中 `ALLOW_REGISTRATION=false` 后重启 editor，以关闭新增账号注册；此时邀请仅能由已有账号接受。

```sh
docker compose up -d editor
docker compose logs --tail=100 editor
```

SQLite 位于 `editor_data` 持久化卷。不要删除卷，也不要将同一个数据库文件交给多个服务实例或放到不支持文件锁的网络盘。当前设计适用于一个小团队、一个服务实例；不支持水平扩容。

当前工作环境未安装 Docker，以上配置未进行容器或公网证书实测；接口与数据库测试在本机 Node.js 环境执行。

## 直接 Node.js 部署

也可以在服务器执行 `npm ci`、`npm run build`，设置以下进程环境变量再执行 `npm start`，使用系统服务管理器维持进程运行：

| 环境变量 | 示例 / 含义 |
|---|---|
| `NODE_ENV` | `production` |
| `PUBLIC_ORIGIN` | `https://story.your-team.com`，必需 HTTPS |
| `HOST` | `127.0.0.1`，由同机 HTTPS 反向代理访问 |
| `PORT` | `3001` |
| `DATABASE_PATH` | `data/story-editor.sqlite` 或持久化绝对路径 |
| `ALLOW_REGISTRATION` | `false` 关闭注册，默认开放 |

`.env` 由 Docker Compose 读取；直接启动 Node 时需要自己设置进程环境，本项目没有自动加载 dotenv。反向代理要支持 WebSocket Upgrade，并允许最高 20 MB 的 JSON 请求。不要用 `npm run preview` 作为远程协作入口，它没有开发代理。

## 备份和恢复

命名快照和恢复前安全快照存在同一个数据库中，不能替代数据库之外的备份。使用 SQLite `VACUUM INTO` 生成一致性文件，允许协作服务继续运行：

```sh
npm run backup
# 或指定一个不存在的目标文件
npm run backup -- backups/team-2026-10-11.sqlite
# 容器内执行，文件落在映射的 backups 目录
docker compose exec editor npm run backup
```

备份包含项目、成员、账号密码哈希、会话、邀请、操作日志和快照，保存在受控目录并复制到独立存储。脚本不自动安排定时任务，不删除旧文件。

完整恢复时先停止 editor；保留当前数据库及其 WAL / SHM 文件作为回退副本，再在持久化卷中恢复备份为 `story-editor.sqlite`，移开旧 WAL / SHM 后重启。恢复前在独立目录和临时实例检查备份，确认项目、成员、快照与记录完整。数据库恢复会恢复当时的账号 / 会话 / 权限状态；它不同于应用内只恢复剧情内容的快照恢复。

## 实现依据与后续验收

共享模型和检查器在 `src/core`；服务端在 `server/index.ts`；客户端提交与草稿在 `src/core/client.ts` / `remote.ts`。

服务器在事务内校验对象版本、修改前值、租约 token 和项目 epoch，原子提交项目及操作日志；提交成功后再广播。结构操作占用被改连线两端节点，并对合并结果进行引用及类型校验。租约保存在进程内，30 秒失效、10 秒续租；重启后全部失效，不复用旧 token。WebSocket 定期 ping / pong 清理失联连接。

本阶段用 SQLite WAL 替代设计文档中的 PostgreSQL；实时更新和重连下发完整权威快照，尚未提供按 revision 补拉增量事件。手动快照及自己的撤销已实现，每日自动快照、字段级合并和协作重做未实现。

上线后按设计文档补做：两条不同网络登录同一项目、5 人同时编辑不同节点、断网期间其他成员修改、租约超时重新抢占、恢复快照使旧稿失效、重启服务后重连、数据库独立备份恢复，以及 300 节点性能测量。本机双客户端测试不能替代这些验收。
